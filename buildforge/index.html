Portable onedir app: extract the zip and run BuildForge.exe. No installer, no services, no registry writes. Settings live in %APPDATA%\BuildForge and uninstalling is deleting the folder.

01 // it detects the stack itself

BuildForge reads the files in the folder and stops at the first real marker, so an ESP-IDF firmware tree is never mistaken for a desktop CMake project. If you pick a wrapper folder that holds exactly one project, it opens that project and tells you where it found it.

02 // errors become explanations

GCC, MSBuild, Python, Rust, npm and CMake output is parsed into a Problems table. Each row carries the file and line, the raw message, why the compiler is complaining and the exact fix. Double-click opens the line in VS Code. 

main.cpp:6:35: error: expected ';' before 'std'
WHY  C++ syntax error: a statement is not terminated.
FIX  Add the missing semicolon on the reported line or the line before it.

03 // toolchains and PATH

BuildForge scans 25 tools at startup, rebuilds PATH from the registry so a compiler installed after login works without a reboot, and refuses to start a build when the compiler for that project is missing. Missing tools show the exact winget command — for ESP-IDF it is winget install --id Espressif.EIM-CLI then eim install.

04 // download and run

  1. Download BuildForge-1.1.0-win64.zip.
  2. Extract the folder anywhere and run BuildForge.exe.
  3. Add your project folder — the type, plan and toolchain check appear immediately.
  4. Press BUILD. Output streams live; errors land in the Problems tab.

05 // command line, same engine

The GUI is a client of the same engine, so scripts can use it too:

buildforge --detect C:\path\to\project --json
buildforge --build C:\path\to\project --debug --jobs 8
buildforge --build . --custom "pytest -q" --timeout 900
buildforge --doctor

06 // honest limits

  • ESP-IDF needs the SDK separately. Detection and the build plan work without it; the app shows the install commands instead of failing cryptically.
  • Plain C/C++ folders are one compiler invocation per build. Great for small tools; large C++ trees belong in CMake or Make, where only changed files are rebuilt.
  • Windows only. The console is built on Tkinter and targets Windows 10/11 toolchains (MSVC, w64devkit, .NET, Node).

07 // verified, not promised
